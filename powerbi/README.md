# Power BI dashboard

A five-page dashboard over a star schema built from the cleaned STATS19 data. It is stored as a **Power BI Project (PBIP)**: a TMDL semantic model plus a PBIR report, all plain text, so it diffs cleanly in Git.

## Open it

1. Install **Power BI Desktop** (free, Microsoft Store), recent enough to open PBIR-format projects.
2. Build the data, if you haven't already:
   ```bash
   python download_data.py
   python -m src.prepare_data          # writes data/powerbi/*.csv
   ```
3. Double-click `powerbi/UKRoadSafety.pbip`, then click **Refresh**. Loading about 2.1M rows takes a minute or two.

If you see an error that the PBIR format is not enabled, go to **File › Options and settings › Options › Preview features**, tick **Power BI Project (.pbip) save option** and **Store reports using enhanced metadata format (PBIR)**, then restart Desktop.

**The CSVs live somewhere else?** Go to **Transform data › Edit parameters › DataFolder** and set the folder path, ending with a slash. You can also regenerate the project with the path baked in:

```bash
python powerbi/build_pbip.py --data-folder "D:/data/uk-road-safety/powerbi/"
```

To publish to the Power BI Service, use **File › Save as › .pbix** first, or publish straight from Desktop.

## Pages

| Page | What it answers | Visuals |
|---|---|---|
| **Overview** | Headline numbers and trend | KPI cards (collisions, casualties, fatalities, adjusted KSI casualties, KSI rate) · collisions per month · recorded vs adjusted KSI share by year · KSI rate by road user · KSI rate by speed limit |
| **When** | Time patterns | Day × hour heatmap · collisions by hour · fatal per 1,000 by hour |
| **Where** | Road environment | Fatal per 1,000 by speed limit, urban vs rural · light · weather · road type · police force ranking |
| **Who** | Road users and age | Share of casualties vs share of deaths · road-user summary table · casualties by age · deaths per 1,000 by age · KSI rate by driver age |
| **Notes** | Definitions and caveats | Method, KSI adjustment, filter behaviour, refresh steps |

Every page except Notes has slicers for **Year, Country, Urban/rural, Police force and Road class**.

## Model

```
dim_date (1,826 rows) 1──* fact_collisions (513,801) 1──* fact_casualties (652,821)
                                                 1──* fact_vehicles   (937,265)
```

- Filters flow from `dim_date` to collisions, then on to casualties and vehicles. Slicing by year, area or force therefore filters every measure. Casualty-level fields such as `road_user` and `age_group` filter only casualty measures.
- `dim_date` is marked as the date table, and auto date/time is switched off.
- Columns used only inside measures (`ksi_adjusted`, `is_fatal`, keys, coordinates) are hidden.

### Measures

| Table | Measure | Definition |
|---|---|---|
| fact_collisions | Collisions | `COUNTROWS(fact_collisions)` |
| | Fatal Collisions | `SUM(is_fatal)` |
| | KSI Collisions (adj) | `SUM(ksi_adjusted)`, where ksi_adjusted = fatal + DfT P(serious) |
| | KSI Rate (adj) | KSI Collisions (adj) ÷ Collisions |
| | KSI Rate (recorded) | share with severity ≠ Slight, unadjusted |
| | Fatal per 1,000 Collisions | Fatal Collisions ÷ Collisions × 1,000 |
| | Injury-based Reporting % | share recorded via CRASH |
| | Collisions YoY % | vs `DATEADD(dim_date[date], -1, YEAR)` |
| fact_casualties | Casualties, Fatalities, KSI Casualties (adj) | counts and sums |
| | Casualty KSI Rate (adj) | KSI Casualties (adj) ÷ Casualties |
| | Deaths per 1,000 Casualties | Fatalities ÷ Casualties × 1,000 |
| | Share of Casualties / Share of Fatalities | over `ALLSELECTED(road_user)` |
| fact_vehicles | Vehicles | `COUNTROWS(fact_vehicles)` |
| | Driver Collision KSI Rate (adj) | mean `RELATED(fact_collisions[ksi_adjusted])` over motor vehicles |

Measures in Power BI match the notebook. For example, overall KSI rate (adj) is 25.3%, and 60 mph roads are 36.5%.

## Regenerate and validate

The project is generated by `build_pbip.py`, which reads the CSV columns and types from `data/powerbi/`. Edit pages, visuals or measures there and rerun it, rather than hand-editing the JSON:

```bash
python powerbi/build_pbip.py
python powerbi/validate_pbip.py     # checks every report file against Microsoft's published JSON schemas
```

The base theme (`assets/CY24SU10.json`) is Microsoft's standard theme, taken from Microsoft's open-source [fabric-toolbox](https://github.com/microsoft/fabric-toolbox) samples. Colours come from the custom theme `UKRoadSafetyTheme.json` and match the notebook figures.

## If Desktop refuses to open the project

The generated files pass schema validation, but the semantic model (TMDL) has no public validator. If Desktop reports an error, it will name the file and line. Either fix it in `build_pbip.py`, or build the model by hand in about 15 minutes:

1. **Get data › Text/CSV**, and load the four files in `data/powerbi/`.
2. In **Model view**, create the three relationships shown above, and mark `dim_date` as the date table.
3. Set **Sort by column**: `dim_date[month]` by `month_num`, and `dim_date[day_of_week]` by `day_num`.
4. Add the measures from the table above. The exact DAX is in `UKRoadSafety.SemanticModel/definition/tables/*.tmdl`.
5. Rebuild the visuals using the page table above.
